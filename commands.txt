AlphaCV, common commands
==========================
Run these from the project root (the folder this file is in).
Every start command rebuilds all images (frontend, backend, model server, workers)
and recreates containers, so code changes are always picked up. Stop commands
never delete volumes (Postgres/Qdrant/Redis/uploads data is safe). Only
./scripts/clean.sh deletes data, and it asks first.

Three stacks (same code, different homes for the data):
  local : everything on this machine, in Docker volumes (Postgres + raw files + Qdrant + Redis)
  dev   : raw files in S3, Postgres on RDS (whatever .env.dev points at)
  prod  : the deployment (docker-compose.prod.yml)
dev and local use the same ports, so run one of them at a time.

BACKUP AND RECOVERY (all three stacks; details in docs/BACKUP_AND_RECOVERY.md)
---------------------------------------------------------------------------
Back up (database + vector store + raw files; only reads the running stack; goes to ./backups/<stack>/<time>/):
  ./scripts/backup.sh local|dev|prod
  ./scripts/backup.sh prod --keep 14          (afterwards keep only the 14 newest)

Check a backup without changing anything, then restore it (asks you to type RESTORE <stack>):
  ./scripts/restore.sh prod backups/prod/<time> --check
  ./scripts/restore.sh prod backups/prod/<time>

LOCAL (all data in Docker volumes - no S3, no RDS)
--------------------------------------------------
Start local (first run creates .env.local from .env.local.example and
forces storage + databases to the local volumes; add your OPENROUTER_API_KEY to it):
  ./scripts/start.sh local

Stop local (keeps the volumes):
  ./scripts/stop.sh local

Start local with a from-scratch build (ignores Docker's layer cache):
  ./scripts/start.sh local clean

Rebuild ONLY the frontend after a UI change (about a minute; backend, workers and data are not touched):
  ./scripts/frontend.sh                 (local, the default)
  ./scripts/frontend.sh dev|prod        (other stacks)
  ./scripts/frontend.sh local clean     (from-scratch frontend build)
Then hard-refresh the browser (Ctrl+Shift+R).

Delete this stack's containers, volumes and images (asks you to type 'delete'),
then rebuild from nothing:
  ./scripts/clean.sh local
  ./scripts/start.sh local clean

Logs / status:
  docker compose -f docker-compose.local.yml --env-file .env.local logs -f
  docker compose -f docker-compose.local.yml --env-file .env.local ps

Local URLs (same as dev):
  Frontend : http://localhost:3000
  API      : http://localhost:8000
  Nginx    : http://localhost
  Monitor  : http://localhost/monitor   (admin login)

Resource limits (docker-compose.local.yml; like prod but smaller, ~6.4 GB of limits in total so it fits in 8 GB):
  match worker 2 CPU / 1.5 GB    backend 1.5 CPU / 1.25 GB    model server 1.5 CPU / 1.25 GB
  qdrant 1 CPU / 768 MB          postgres 1 CPU / 384 MB      background worker 0.75 CPU / 512 MB
  frontend 0.5 CPU / 384 MB      redis 0.5 CPU / 320 MB       nginx 0.25 CPU / 64 MB
Live usage:  docker stats --no-stream
More concurrent matches:  docker compose -f docker-compose.local.yml --env-file .env.local up -d --scale match-worker-local=2
  (each extra match worker adds up to 2 CPU / 1.5 GB; only do it if the Docker VM has the memory)

Where the data lives (docker volume ls):
  alpha-cv-local_postgres-local-data   Postgres (users, tracker)
  alpha-cv-local_qdrant-local-data     CV / JD index and embeddings
  alpha-cv-local_uploads-local-data    raw CV and JD files
  alpha-cv-local_redis-local-data      queues + caches

USEFUL EXTRAS
-------------
View live logs (dev):
  docker compose -f docker-compose.dev.yml --env-file .env.dev logs -f

View live logs (prod):
  docker compose -f docker-compose.prod.yml --env-file .env.prod logs -f

Check container status (dev):
  docker compose -f docker-compose.dev.yml --env-file .env.dev ps

Check container status (prod):
  docker compose -f docker-compose.prod.yml --env-file .env.prod ps

Wipe application data only (keeps auth users + all volumes, asks to confirm):
  ./scripts/db/reset_data.sh dev
  ./scripts/db/reset_data.sh prod

Run backend tests:
  cd backend
  python3 -m pytest tests/ --no-cov

Run backend offline end-to-end smoke test:
  cd backend
  PYTHONPATH=. python3 tests/e2e_smoke.py

Build frontend locally (without Docker):
  cd frontend
  npm run build
